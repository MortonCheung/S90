# 阶段08 · 详情信息不得无故闪退、消失再出现

## 唯一需求

在阶段07已实现的双栏中，优化**详情内容的生命周期、章节切换与滚动阅读**。不得同时改相机路径/车漆/字体体系。

## 当前问题

- `src/story/story.js::DETAIL_BANDS/detailState` 使 `detail.id` 在每个区间边缘变为 `null`；五个区间之间可能存在无详情窗口。
- `src/detail/DetailPanel.jsx` 在 `open=false` 时使用 `last` 保留内容，但真正显示行为依赖 `data-open`，CSS 又以 `opacity` 和 `visibility` 隐藏整个容器。
- `<div className="detail__inner" key={data.id}>` 导致章节变化时内容DOM整块重建；如同时遇到面板关闭，会产生“消失一下再突然出现”的感觉。

## 用户期望

进入一个信息阅读章节时，右栏先展开并稳定存在；接下来文字/配图按用户滚动自然衔接，内容换章不应该让右栏整块消失或短暂留空。真正从详情回到全屏叙事时，才收起整个阅读区。向上滚动完全逆向恢复。

## 施工步骤

1. 分清两个状态：`layoutOpen`（双栏是否需要存在）与 `activeContentId`（右栏显示哪段内容）。两者**不可用同一个布尔/ID直接决定**。先设置章节展示矩阵：哪些是全屏间奏、哪些是连续详情序列。
2. 为阅读态定义明确起止边界，以及**章节之间的内容过渡点**。用户未要求每个部位都必须经过全屏间奏，所以优先保证详情连续；需要全屏镜头的章节再单独定义。
3. 在内容跨章节时让右栏布局持续打开，新文字与旧文字做克制的短时过渡（例如 0.2–0.35s），**不要先隐藏整块布局**。新内容未准备好时暂时保留上一段，而不是清空。
4. 避免 `key={id}` 引发整棵内容节点重置和高度突变。可让两个内容层在一个固定栏位上交叉过渡，过渡完成后再移除旧层；若做文本逐项滚动，更需维护稳定阅读容器。
5. 若详情可滚动，明确浏览器滚动负责主线。不能出现“用户滚轮卡在右侧、左侧汽车还自己转”的冲突。
6. 反向滚动时恢复上一条内容、对应镜头与布局；严禁“恢复时先显示新章再跳回旧章”。
7. 保留与实际车型有关的标题/配图/说明，避免重复微小规格表；文字真实性应与模型、官方车型信息和版权资料交叉核实。
8. 用浏览器进行 0.15→0.20→0.25→0.33→0.46 等顺/逆序滚动测试，并录制不同速度的滚动视频。

## 代码示例：状态分离

```js
// 仅示意：根据当前章节表返回两个**不同**状态
export function getDetailPresentation(progress, chapters) {
  const active = chapters.find(c => progress >= c.start && progress < c.end);
  if (!active) return {layoutOpen:false, activeContentId:null};
  return {
    layoutOpen:true,                   // 同一详情组内持续展开
    activeContentId:active.contentId,   // 可以变化，但不触发 layoutOpen=false
  };
}
```

```jsx
// 页面根布局读取 layoutOpen + detailFactor；右栏文字独立管理 activeContentId
<VisualLayout detailFactor={presentation.factor} car={<Experience /* ... */ />}
  details={<DetailContent activeId={presentation.activeContentId} />}/>
```

## 验收

- 同一个详情组内换内容，右栏没有“整块消失→出现”；图文保持视觉连续。
- 全屏间奏只在设计指定的位置发生，关闭/展开路径可逆。
- 正向与反向滚动的章节对应关系正确，任意区间停下没有闪烁或未渲染内容。
- `DetailPanel` 内按钮在面板不可见时不抢焦点；关闭时焦点回到可见的合理位置。
- 录屏至少覆盖连续两个部件详情并反向恢复，`STAGE-08.md`。
