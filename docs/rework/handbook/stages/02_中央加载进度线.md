# 阶段02 · 中央横线是唯一加载进度条

## 唯一需求

让开场中线从左向右随着**真实资源状态**增长，去掉左下角重复进度条。此阶段**不改分界线的揭幕动画**（阶段03负责）。

## 当前行为（有源码证据）

- `.opening__line` 在 `src/styles/global.css` 是 `left:0; right:0` 的静态渐变线，整个视口从开始就存在；没有绑定加载进度。
- `Opening.jsx` 下方 `.opening__status-bar > span` 才依据 `progress` 设置 `scaleX`。
- `useCarAsset.js` 仅提供 GLTFLoader 下载回调 `event.loaded/event.total`，下载到100%≠着色器编译/第一帧已显示。

## 期望行为与状态机

- `LOADING_BYTES`：页面中央水平进度线根据**已知** loaded / total 增长，逐渐伸向右侧；如总字节未知，使用明确的无限状态动画，**不展示假百分比**。
- `PREPARING_RENDER`：下载已经完成，但尚未满足首帧条件；保留完整横线，辅以一处非常轻微的端点活跃提示，而不是伪装成95%继续增长。
- `READY_TO_REVEAL`：线稿完成 + 真实3D准备好，进度线达到满幅；阶段03可将该线接管为上下裂幕边界。
- `ERROR`：显示简单的“加载失败 / 重试”文本，线条暂停，不无限自动重试。

## 施工顺序

1. 在 `src/opening/Opening.jsx` 中移除左下 `.opening__status-bar` 和相关 `.opening__status-meta` 等纯装饰布局；保留必要的错误语义和重试按钮。
2. 修改 `.opening__line` 为“轨道 + 当前实进度”结构，作为**唯一**可见加载进度条；其最终布局位置就是揭幕分界位置，不要重做另一条独立分界线。
3. 区分下载阶段和准备渲染阶段。`progress` 只代表下载比例，不伪造整体任务百分比；资源无法报告总量时展示 `indeterminate` 而不是0%、95%等。
4. 在 React 中使用明确的 `data-state`、`role="progressbar"` 及 aria 属性（有真实百分比时）；元素文字要简洁、可关闭。
5. 保留 `prefers-reduced-motion` 的退化行为。
6. 分别模拟正常下载、慢速下载、未知总量、下载中断和完成但未渲染五种状态，录屏对照确认线条不会提前满幅后误揭幕。

## 代码示例：进度状态派生

```js
// src/opening/loading-state.js
export function getLoadingVisual({ assetStatus, progress, total, firstFrameReady }) {
  if (assetStatus === 'error') return {state:'error', fraction:0};
  if (assetStatus === 'ready') {
    return firstFrameReady
      ? {state:'ready', fraction:1}
      : {state:'preparing', fraction:1};
  }
  if (!(total > 0)) return {state:'indeterminate', fraction:null};
  return {state:'loading', fraction:Math.min(1, Math.max(0, progress || 0))};
}
```

```jsx
// 片段：替换旧 .opening__line 的可视部分
const visual = getLoadingVisual({assetStatus,progress,total,firstFrameReady});
<div className="opening__line" data-state={visual.state}>
  <div className="opening__line-track" />
  <div
    className="opening__line-fill"
    style={{transform:`scaleX(${visual.fraction ?? 0})`}}
  />
</div>
```

```css
.opening__line {position:absolute;left:0;right:0;top:50%;height:2px;z-index:56}
.opening__line-track {position:absolute;inset:0;background:rgba(17,19,22,.10)}
.opening__line-fill {position:absolute;inset:0;background:#111316;transform-origin:left center;will-change:transform}
.opening__line[data-state="indeterminate"] .opening__line-fill {transform:none !important; /* 另用不代表百分比的短游标动画 */}
```

> 上述代码为可改造示例，不是粘上后立即完成。`assetStatus` / `total` / `firstFrameReady` 要先从真实 App 和 useCarAsset 数据传入，保持原本单 Canvas 架构。尤其不要把 `assetStatus === 'ready'` 直接当成首帧可见。

## 行为边界

- 不允许把动画进度冒充下载进度；允许线稿进度和资源进度互不相同。
- 资源先完成，线稿继续时保持满条；线稿先完成，资源仍在准备时保持原画面并等待。
- 不新增第三个进度条；不在左下角重复显示同一任务状态。
- 不重写阶段01的路径动画；不提前改变揭幕机制。

## 验收

- 页面中央有且只有一条明确的进度线；从左到右的长度能对应真实字节进度。
- 未知总量显示不确定状态，绝不显示虚假100%。
- 通过正常/慢速/错误/下载后渲染等待测试；错误重试有效。
- 生成 `docs/rework/reports/STAGE-02.md` 和各状态截图，不允许只贴 CSS 截图。
