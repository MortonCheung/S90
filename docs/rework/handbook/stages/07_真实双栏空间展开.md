# 阶段07 · 从全屏变双栏：右侧真正“推开”画面

## 唯一需求

重构布局层。将当前 fixed 右侧覆盖层替换为真正的两列空间布局：右栏展开时左侧3D展示区同步收缩并重新构图。**本阶段不修改详情文案与内容切换策略（阶段08）。**

## 已确认的旧实现

- `src/detail/DetailPanel.jsx` 返回 `<aside className="detail">`，位于 `App.jsx` 中 `.stage` 之外。
- `global.css` 定义 `.detail { position: fixed; right:0; width:min(520px,40vw); ... opacity/translateX }`，本质上盖在画面上。
- `CameraSystem.jsx` 使用 `camera.projectionMatrix.elements[8] += 0.38 * detailFactor` 和少许退距来避让，**不是真正的左栏缩放**。

## 视觉目标

参照 https://spykercars.com/c8-preliator 和 https://illoca.unseen.co ：一开始汽车在全屏；到达展示点，右侧**真实分配**一块白色内容阅读区域，左侧画面被推向左侧，三维相机根据可用宽高比重新构图（不是汽车被右栏遮住）；结束后两列合拢恢复全屏。整个过程车模始终持续可见，正反向滚动逐帧一致。无人工添加的大面积毛玻璃边框。

## 实施步骤

1. 建立公共 `VisualLayout` 组件（或等价架构），容纳左侧 `Experience` 和右侧 `DetailPanel`。两个元素属于同一 grid/flex 容器，不再分别 fixed 叠在视口顶部。
2. 用 `stateRef.current.detailFactor` 或统一布局状态驱动右侧列宽**从0平滑增长至目标宽度**。关键是两列尺寸有总和约束（无空洞、无重叠）。
3. 同步记录左侧容器的实际像素宽度、高度，R3F `Canvas` 跟随 ResizeObserver 更新渲染尺寸/相机 aspect；不要只裁切固定宽度全屏 Canvas。
4. 将新的可用视口宽度反馈给 `CameraSystem`，重新安排构图；不能保留旧的 `elements[8] += 0.38 ...` 人工避让作为核心方案。必要时只做微量 lens shift，但应先在新容器中正确使用宽高比。
5. 使右栏标题/内容在展开过程的中后段显现，避免0宽度时内容溢出；右栏应 `min-width:0; overflow:hidden`。收合时相反顺序。
6. 测试鼠标滚轮在右栏内的语义：主线仍依据页面进度，内容较多时确保阅读和滚动不产生冲突；不要让独立滚动容器吞掉主线输入造成卡死。
7. 处理手机：将右侧改为**底部详情区域**，不直接把桌面窄侧栏压得更窄；车仍能看到主要部位。
8. 围绕 wheel/detail/focus 做截图：0%、20%、50%、80%、100%展开以及同样的逆向收合。

## 结构示例：真正的两个空间列

```jsx
function VisualLayout({detailFactor,car,details}) {
  const [width,setWidth] = React.useState(window.innerWidth);
  React.useEffect(()=>{
    const handler=()=>setWidth(window.innerWidth);
    window.addEventListener('resize',handler);
    return ()=>window.removeEventListener('resize',handler);
  },[]);
  const detailWidth = Math.round(Math.min(520,width*0.4)*detailFactor);
  return <div className="visual-layout" style={{'--detail-width':`${detailWidth}px`}}>
    <section className="visual-layout__car">{car}</section>
    <aside className="visual-layout__info">{details}</aside>
  </div>;
}
```

```css
.visual-layout {position:fixed;inset:0;display:grid;grid-template-columns:minmax(0,1fr) var(--detail-width);overflow:hidden}
.visual-layout__car {position:relative;min-width:0;overflow:hidden}
.visual-layout__info {min-width:0;overflow:hidden;background:#f4f1ea}
.visual-layout__car canvas {display:block;width:100%;height:100%}
@media (max-width:820px){
  .visual-layout{grid-template-columns:minmax(0,1fr);grid-template-rows:minmax(0,1fr) var(--detail-height)}
}
```

> 以上是**结构示例**。在现有工程中避免 `useState` 每帧更新宽度；可使用 root ref + CSS 自定义属性或轻量动画，让滚动主时钟统一写入，而不是使 React 整树每帧重渲染。移动端还要传入真实 `--detail-height`，不能只复制 CSS 不给值。

## 强制校验

- 在页面 DevTools 里测量：展开时左侧 Canvas 包围盒宽度确实减少，右侧阅读区宽度确实增加；两者不重叠。
- 左侧车灯/轮毂完整落在左栏；不得由于横向缩小把目标裁去。
- Canvas DOM 计数始终为1；WebGL renderer 不能重新建立；GLB 网络请求数不增加。
- 正向/逆向动画无突跳，停在50%时布局应稳定；移动端不得出现横向溢出。
- 大屏显示为独立、不透明、干净的右栏；禁止旧 fixed 毛玻璃遮挡方案遗留。
- 保存测量值、分帧截图和 `STAGE-07.md`。
