# 阶段01 · 让汽车由左向右“被画出来”

## 唯一需求

重构手绘动画的路径组织与播放节奏。**不调整中央进度条、揭幕、模型、相机或页面版式。**

### 当前行为（有源码证据）

- `src/opening/Opening.jsx` 将约921条路径按 `LAYER_ORDER`、长度排序；每条仅以 `order * 0.0032` 秒错开，单条最长约0.94秒。大型剪影很快勾完，剩下路径密集出现，缺乏“生长”过程。
- `tools/lineart/trace.js` 使用闭合 silhouette 和按 Mesh 边缘抽取的细碎多段路径；有些路径自带多个 `M`，并不适合逐笔动画。
- 用户反馈“线条画得好，但太快地勾全车，更像黑色块浮现”。

### 期望行为

严格侧视图保留。观众能够追踪**最多2–3个同时活动的笔触前沿**，从画面左方向右方移动：A=外轮廓/车身腰线，B=车窗/柱体/轮拱，C=车灯/轮毂/门把手局部。早期只有几条正在绘制的线，不出现已经完成的完整车身剪影。整个明显可见的绘制序列建议4.8–6.5秒（是首版调校区间，不是固定硬编码）；25%/50%/75% 截图必须能看出明确递进。

## 来源示例

- 用户参考： https://heronaiapp.com （建筑线条连续绘制，不是大片淡入）。优先查看用户上传的 `录屏2026-11-03 11.37.09.mov`。
- GSAP SVG 文档： https://gsap.com/docs/v3/Plugins/DrawSVGPlugin/ ，它解释 `strokeDasharray`/`strokeDashoffset` 的原理；**不要求添加新付费依赖**，当前 GSAP 配合原生 stroke 即可。

## 施工步骤

1. 读取 `public/assets/lineart/s90-side.svg`，生成路径审计 JSON：每条 path 的 `data-layer`、长度、起点/终点、包围盒 `minX/maxX`、是否闭合、是否包含多个独立 M 段。特别标记外轮廓路径。
2. 只在这一步设计一份**手绘笔划清单** `src/opening/stroke-plan.js`。对关键长路径进行人工审美选择和必要的重组：用同一幅 SVG 的可见轮廓描画，不重新手工虚构不匹配的轮廓；复杂闭合剪影拆成可定向的弧段，要求起笔方向左→右。
3. 创建三个独立绘制轨道。每轨在任意时刻最多一个主要笔触；轨道可以有轻微重叠。不允许一次性启动大批细碎路径。线条整体可由左→右推进，但局部轮胎圆弧允许围绕一个点形成闭合笔画。
4. 调整细节的视觉权重：主轮廓先于小修饰；轮毂格栅的密集边线不要抢主笔触。未到达当前生长前沿的路径必须不可见。
5. 尽量保持现有 SVG 线稿与车模同视角对齐。不得使用复杂蒙版替代“笔迹增长”的主体效果；如使用左右推进的裁剪，只能辅助手绘 dash 动画。
6. 对 `prefers-reduced-motion` 直接显示完成态，确保最终线稿依旧完整。
7. 使用 Playwright 定时截取至少6个时刻（0%、20%、40%、60%、80%、100%），保存时间标记并组织一张 contact sheet 供验收。

## 可直接改造的代码示例：确定性笔触编排

示例展示**数据结构和推进逻辑**；`path` 的轨道、先后顺序必须由实际 SVG 检查决定，不能盲目套所有921条。

```js
// src/opening/stroke-timeline.js
import gsap from 'gsap';

export function createStrokeTimeline(groups, onDone) {
  // groups = { body: [SVGPathElement,...], cabin: [...], detail: [...] }
  const lanes = [
    {name:'body', start:0, speed:520},
    {name:'cabin', start:0.65, speed:460},
    {name:'detail', start:1.4, speed:390},
  ];
  const tl = gsap.timeline({paused:true, onComplete:onDone});

  for (const lane of lanes) {
    let cursor = lane.start;
    for (const path of (groups[lane.name] || [])) {
      const length = path.getTotalLength();
      if (!Number.isFinite(length) || length <= 0) continue;
      // 数据预处理必须已确保关键笔划起点在左；否则先反向重建 path。
      gsap.set(path,{strokeDasharray:length,strokeDashoffset:length,visibility:'visible'});
      const duration = Math.max(0.18, length/lane.speed);
      tl.to(path,{strokeDashoffset:0,duration,ease:'none'},cursor);
      cursor += duration;   // 同一轨只有一笔在画
    }
  }
  return tl;
}
```

**易错提醒：** `strokeDashoffset` 只保证沿 path 的固有方向绘制，无法自行把一条从右→左定义的路径变成左→右。路径分段、首尾反转、轨道编排和按 X 范围调度才是此阶段重点。若 path 中有多个独立 `M`，先拆分，不要把多段一并当一条笔划绘制。

## 验收（必须人工/模型视觉检查截图）

- 0–20%没有完整车身闭合剪影；40%左侧已经成形但右侧显著未完成；80%整体近完成但仍有局部笔迹活动；100%车轮、窗、灯、车身齐全。
- 从左→右的推进方向不反复大幅跳回；同一时刻最多3个显著笔尖/生长前沿（允许局部微弱补笔）。
- 无“黑色面块渐变显现”代替画线，无大量线条同时闪现。
- 线稿最终轮廓与原版及真实车模基本一致；移动端不因裁剪丢车轮。
- 实际录屏附在 `docs/rework/reports/01-linegrowth.mp4` 或提供逐帧截图集；生成 `STAGE-01.md`。

## 失败处理

若 SVG 原数据过碎，先针对 20–40 条核心线条生成精简绘制层，把其余细节留到真正绘制完成后少量补笔；不要通过增加500个新定时器掩盖问题。若经过两轮调度仍无法满足生长感，允许在保持模型侧视几何一致的前提下手工描整车主要样条，记录几何/视觉对齐误差。
