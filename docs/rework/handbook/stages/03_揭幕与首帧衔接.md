# 阶段03 · 线条裂幕到真实3D的无缝衔接

## 唯一需求

修正**揭幕时机、上下裂幕动画、同位对齐**，不碰已验收的线稿节奏与中央进度逻辑。

## 当前代码问题

- `App.jsx`: `const onFirstFrame = useCallback(() => {}, []);` 是空函数，`Opening.ready` 用 `asset.status === 'ready'`，未真的等待首帧。
- `CarModel.jsx` 虽然在 `requestAnimationFrame` 中调用 `gl.compile` 和 `onFirstFrame`，但 callback 当前未改变任何状态。
- `Opening.jsx` 用 `ready && drawn && markup` 开始上下两片 `yPercent:-50/+50`，同时线条逐渐透明；需要证明剥离时底层真车真正已经可见。

## 预期交互

线稿完全绘制并且中央加载线准备完成 → 同一位置的真实 S90 在底层已成功渲染 → 中央横线作为边界向上、向下移动 → 纸面退出、汽车在露出的区域中持续可见 → 不闪白、不黑屏、不突然重建场景 → 揭幕结束后只出现清晰的“向下滚动”提示。

## 施工步骤

1. 将 `firstFrameReady` 加入 App 状态，由 R3F 真实渲染生命周期更新。首帧标记至少应在模型加入场景并且着色器编译成功后的一个已完成渲染帧触发；不能仅在下载回调中标记。
2. 明确 `assetLoaded` / `shaderPrepared` / `firstFrameReady` / `lineartFinished` 四种条件。真正开始揭幕要求 `lineartFinished && firstFrameReady`。
3. 保留原来的 `.sheet--top` 和 `.sheet--bottom` 布局，但修正“纸片移动距离”与“裁剪边界”的一致性；让中央进度线在 READY 后自然成为两侧裂幕边缘，避免进度条突然换一条线。
4. 检查开场相机是否和线稿生成的 `openingPose()` 一致；特别是 16:9 与竖屏/窗口缩放。如果要调整投影，必须同步更新线稿生成和前端投影计算。
5. 保持 Model/Canvas 在整个开场、叙事、探索过程中均不重新挂载，`React` 不应通过 `key` 强制重建 WebGL。
6. 捕获揭幕0%、10%、25%、50%、75%、100%连续画面，检查车模是否贴合线稿轮廓，是否存在跳动或突变。
7. 测试 WebGL 失败和资源加载失败：页面显示可恢复的信息，不让用户永远卡在线稿上。

## 示例：把首帧状态传递到开场

```jsx
// App.jsx，替换空实现并传递状态
const [firstFrameReady, setFirstFrameReady] = useState(false);
const onFirstFrame = useCallback(() => setFirstFrameReady(true), []);
const canReveal = drawn && asset.status === 'ready' && firstFrameReady;

<Experience onFirstFrame={onFirstFrame} /* 其他现有 props 不变 */ />
<Opening
  ready={canReveal}
  drawn={drawn}
  firstFrameReady={firstFrameReady}
  /* 传入真实 progress / total、现有错误与回调 */
/>
```

> 只连接 `onFirstFrame` 仍不足以证明 GPU 图像完成：Agent 要在 `CarModel.jsx` 验证该回调触发时机（可结合 `gl.compileAsync` 可用性和已渲染帧）、失败路径和真实浏览器录屏，不得仅用两次 `requestAnimationFrame` 就宣称零闪屏。

### 更稳定的状态机思路

```js
const phase = !lineartFinished ? 'drawing'
            : !firstFrameReady ? 'waiting-for-render'
            : 'reveal-ready';
// 只允许从 reveal-ready 触发一次正式揭幕；失败后须重置状态与动画。
```

## 边界

- 不在揭幕瞬间创建/载入车模型；不能用汽车截图假装真实3D。
- 不能提前解锁滚动；用户滚轮输入应在 `onOpened` 后进入正常叙事进程。
- 不改变已验收线稿的画面位置、大小；若必须修复同位误差，用线稿/相机共同坐标源处理。

## 验收

- 揭幕前与揭幕后车身轮廓误差处于可接受像素尺度（桌面1600×900可参照旧项目0–3px基线）；若超过明确记录原因。
- 无一帧只有空背景或尚未完成材质的模型。
- 慢网、失败重试、窗口缩放、正常网络均可复现。
- 记录完整揭幕阶段录屏和 `STAGE-03.md`；进入阶段04。
