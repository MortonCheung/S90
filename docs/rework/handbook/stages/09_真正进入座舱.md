# 阶段09 · “内饰章节”必须真正进入车内

## 唯一需求

将当前隔着外部车窗看向座舱的“内饰章节”，改为**真实车内观察视点**：首先能够看清仪表台、中控、方向盘、前排座椅；可选增加后排乘坐空间镜头。不得简单以一张车内照片替代实时3D。

## 已确认代码事实

`src/story/story.js` 中 cabin 镜头当前 `pos [-3.9, 1.2, 1.1]`，远在车外；`target[-0.2, 0.95, 0.4]` 并不足以构成进入座舱。`docs/reports/STAGE-05.md` 明确指出模型优化后的内饰大幅简化。

## 期望效果

从外观沿车窗靠近，画面有清晰的内外过渡；随后摄像机位于真实座舱空间，能够稳定观察方向盘/中控与座椅，不被车顶、B柱、玻璃遮挡。过渡必须和主线连续，反向滚动恢复外侧视点；不存在“镜头突然瞬移到车里”的硬切。

## 必须先核实的能力

1. 打开阶段04确定的外观/内饰资产，在开发视图中定位 `Dashboard`、`Steering`、前排 `Seats`、`Console`、车窗玻璃、车顶/车门内衬的真实世界包围盒；检查这些物体是否能在近景下保持视觉质量。
2. 如果优化版内饰质量不足，允许从用户提供的原始 GLB 中提取更高精度座舱层，或选择外观+内饰的 LOD 组合。不得以重新大幅压缩导致又失去内饰细节。
3. 如果原始高精文件无法访问，记录 BLOCKED：可以继续完成其它章节，但不能把外视图写成“真正进入座舱 PASS”。

## 施工步骤

1. 开发模式下显示车体坐标、重要内饰部件中心和可视化相机路径。确认安全的镜头入口在左/右侧窗位置，且与当前外观章节衔接。
2. 设计至少三个关键姿态：`approachWindow`（从车外接近）、`crossThreshold`（穿越玻璃/车门区域的过渡）、`interiorHero`（真正位于舱内，注视仪表台/方向盘），可选 `rearSeat`。
3. 从窗口过渡时可用短时车窗材质淡出或结构可见性处理，但必须**只在座舱过渡区间使用**，并恢复原始材质。不要在全站把所有玻璃强制透明或删除。
4. 进入舱内时调整 camera.near（例如从0.05适度减小），防止仪表/座椅近距离裁切；恢复外景时也恢复相应设置。测真实遮挡情况，不要靠关掉整个车顶来作弊。
5. 在镜头停留段让仪表台、中控和座椅可辨；不要持续快速绕转。内饰如果只支持单一低质量材质，不要强制实现额外颜色切换作为主线功能。
6. 正向滚动从车外进入，再从车内沿合理路径退出到车尾主线；逆向滚动必须能恢复，包括玻璃透明状态和相机位置。
7. 在桌面、手机宽度截取车内 Hero、方向盘细节、座椅构图；如果某些机位因模型缺陷不可用，调整观察点或准确记录限制。

## 可直接改造的过渡状态示例

```js
const smooth = (a,b,x) => {
  const t=Math.max(0,Math.min(1,(x-a)/(b-a)));
  return t*t*(3-2*t);
};

// 只有座舱过渡区间才改变玻璃可见度；所有相关材质需记录原始属性
export function cabinWindowOpacity(progress, enterStart, enterEnd, exitStart, exitEnd) {
  const fadeOut = smooth(enterStart,enterEnd,progress);
  const fadeIn = 1 - smooth(exitStart,exitEnd,progress);
  // 中段淡出，结束后回到初始状态
  return 1 - Math.min(fadeOut,fadeIn);
}
```

> 上面只是区间曲线模板；**务必实际检查代码在所有区间的数值**：例如当前示例中 exitStart 前 `fadeIn=1`，可实现中段 `opacity=0`，进入前 `opacity=1`，结束后 `opacity=1`。若车窗有多个材质并包含遮挡后视结构，应按对象分别处理。相机走位必须使用真实测量的点位。

## 行为边界

- 不制作“内饰”静态图片硬切，不穿过实心车门/座椅。
- 不引入新的 WebGL Canvas 或重新加载整辆车。
- 不在主视觉使用可疑的原厂配置参数；素材与概念配色明确标注。
- 内饰优化失败时严禁静默降级为外窗观察却标记 PASS。

## 验收

- 记录至少两张**相机位置真实处于座舱内部**的截图，附开发模式相机世界坐标及部件遮挡验证。
- 可辨认仪表、中控、座椅，而不是窗玻璃反射。
- 外→内→外连续，正反向滚动状态与材质恢复一致。
- 保存 `STAGE-09.md`、镜头路径图/录屏；如果无法实施则记录明确的 BLOCKED，绝不可假完成。
