# 阶段11 · 视觉行为回归测试（不是仅看 Build PASS）

## 唯一需求

对阶段01—10做独立、真实的视觉回归与性能验收，验证新效果确实解决问题。除修复测出的缺陷外，不新增功能、不改叙事内容。

## 测试环境与原始证据

使用既有 `tools/qa.mjs`、`tools/verify.mjs`、`tools/shoot.mjs` 或补充 Playwright 自动化；必须去除所有其他比赛目录的绝对路径。保留测试命令、浏览器版本、是否真实 GPU/SwiftShader、viewport、设备像素比和日期。参考文件是项目自己的实际截图/录屏，不是网上搜的汽车广告图。

## 可执行的 Playwright 验证示例

```js
import {chromium} from 'playwright';
import fs from 'node:fs';
fs.mkdirSync('docs/rework/reports/qa',{recursive:true});
const browser=await chromium.launch();
const page=await browser.newPage({viewport:{width:1600,height:900},deviceScaleFactor:1});
const errors=[];
page.on('pageerror',e=>errors.push(String(e)));
await page.goto('http://127.0.0.1:5177',{waitUntil:'domcontentloaded'});
await page.waitForSelector('.site-head[data-dim="false"]',{timeout:60000});
const max=await page.evaluate(()=>document.documentElement.scrollHeight-innerHeight);
for (const t of [0.20,0.33,0.46,0.59,0.715,0.97,0.46,0.20]) {
  await page.evaluate(y=>scrollTo({top:y,behavior:'instant'}),Math.round(max*t));
  await page.waitForTimeout(500); // 允许滚动缓动收敛；不是固定动画时长断言
  await page.screenshot({path:`docs/rework/reports/qa/p-${t.toFixed(3)}-${Date.now()}.png`});
}
const canvasCount=await page.locator('canvas.scene').count();
console.log({canvasCount,errors});
if(canvasCount!==1 || errors.length) process.exitCode=1;
await browser.close();
```

上述脚本仅检查主线基本状态，**不能代替视觉验收**。特别是快滚动会绕过视觉内容，要同时录制真实滚动过程并检查每一段。只要画面仍显著粗糙、镜头乱晃或双栏覆盖，即使测试返回0也必须 FAIL。

## 绩效测试

- 记录真实运行机器、GPU、浏览器、采样区间、平均/最低 FPS 或帧时间分布；headless Chromium 的性能数据仅对该环境有效。
- 对比优化前后首次模型下载时间、首帧可见时间、总传输字节、JS bundle；不能只显示“模型14MB”就宣称网页快。
- 移动仿真不等于真机测试。若不能实际用 Safari / Android 验证，在报告中标记 UNVERIFIED。
- 模型资源失败、WebGL 上下文丢失、弱网络重试等异常必须有证据；不能通过注释绕过错误。

## 视觉评审硬性问题

1. 把6帧线稿排成一组：全车轮廓是否过早出现？
2. 同机位左右对比粗糙旧车与新车：是否真的更精细，而不是仅调亮？
3. 逐个镜头暂停：看不出正在展示哪个部位就不合格。
4. 双栏半开截图：右侧是否真实占有空间？汽车是否移入左侧？
5. 车内截图：摄像机是否真的置于座舱里面？
6. 页面UI：有没有仍然没有价值的小字/按钮？

## 判定与回修

FAIL必须定位到造成问题的阶段并在回修提交里注明 `fix(stage-xx): ...`，修完重测。BLOCKED不得被标PASS；如因缺原始 GLB 而无法真实实现内饰，需要如实交付“该必需项未完成”，不能用文字报告掩盖。
