# 00 · 总控施工规范（唯一上位约束）

## 一、任务定义

**输入**：现有 `MortonCheung/S90` 仓库、可获得的原始 S90 GLB、参考网站/录屏、本目录下的14份独立需求手册。

**当前行为**：初版功能齐全，但 SVG 外轮廓瞬间出现；中央横线不是进度条；14.54 MB 车模观感粗糙；9个镜头坐标插值缺少明确摄影意图；右侧详情为 fixed 覆盖层，内容显隐断裂；所谓座舱镜头还在车外；页面冗余小字与控件太多。

**期望行为**：在不丢失现有成果的前提下，完成可逆的连续豪华汽车叙事，并在桌面端真实复核画面质量。

**终止条件**：第00—13阶段均有独立报告；必修项通过代码、视频/截图和浏览器行为验证；可构建可运行；新材料与新版画面相符；安全推送到 `MortonCheung/S90` 的整改分支并提供确切分支/提交。不得仅凭“所有阶段已写 PASS”宣布成功。

## 二、执行方式——用户不参与逐阶段批准

只允许**一个阶段处于 ACTIVE 状态**。执行完当前阶段并自验后，在 `docs/rework/reports/STAGE-XX.md` 记录 PASS / FAIL / BLOCKED / UNVERIFIED、命令和输出、截图链接、修改文件和 Git SHA。PASS 自动执行下一阶段；FAIL 必须自行定位修复并复测；阻断时记录并继续不依赖该任务的其他阶段，最后归总。不要为了按序推进把 FAIL 改写为 PASS。

无论任务如何复杂，**不要要求用户每阶段发送“继续”**。你被授权在现有仓库中进行可回滚的代码修改与本地测试；网络推送按本规范进行。需要登录、安装会修改系统全局配置的工具、付费资源、提交正式参赛平台、不可逆删除等仍需遵守真实的权限和风险边界。

## 三、版本控制：绝不能覆盖既有成果

1. 首先 `git fetch`、确认 HEAD / 远端差异 / 工作区状态和当前分支；如工作区含用户未提交修改，先保留，不允许 `git reset --hard`。
2. 以当前远端 `origin/main` 为基线新建 `refactor/s90-visual-storytelling-v3`（如同名分支存在，先检查并采用安全的新分支）。可使用 `git worktree` 隔离，不能把旧 M4 仓库当成推送目标。
3. 每阶段单独提交，提交格式 `fix(opening): ...` / `refactor(camera): ...` / `test(visual): ...`，不得跨阶段乱提交。
4. `main` 中原始三张展板、说明 PDF、demo 视频和验证记录必须保留为可恢复快照。新版生成文件写入新的工作目录或在保留快照后受控更新。
5. 若无法执行 Git 推送，保留本地提交和补丁，不强推、不覆盖远端；结尾说明需用户处理的唯一权限阻断。不要自动改写 main 历史。

## 四、阶段间硬性边界

- 阶段01只改线稿顺序、时长和笔触表现；不能同时改颜色、照明、相机或版面。
- 阶段02只改加载指示 UI 与状态映射；不借“优化进度”偷偷重做揭幕。
- 阶段03只修首帧闸门、上下裂幕与同位对齐；不重做整站开场视觉。
- 阶段04只处理原模型与优化产物的质量，不在本阶段调整页面排版。
- 阶段05只处理材质、灯光、曝光、反射和地面，不改变车体几何与摄影分镜。
- 阶段06只处理相机路径和停顿；阶段07只处理空间重排；阶段08只处理内容过渡；阶段09只处理真正座舱视点/资源；阶段10只做信息减法。
- 阶段11只做测试和必要的缺陷回修（回修提交关联原阶段）；阶段12才制作展板/视频；阶段13进行整体验收与交付。

## 五、工程不变量和禁忌

- 单一 R3F `<Canvas>`，单一 S90 模型实例、单一主相机所有权；不能为每个章节重新加载 GLB。
- 正常滚动推进时间轴；**向上滚动必须回到之前的空间与内容状态**。探索模式镜头控制权必须和故事镜头互斥。
- 禁止镜头穿模、出现画面黑屏、首帧错误纹理、暂停滚动仍缓慢漂移、右侧遮盖车身、面板无故闪退。
- 禁止伪造下载百分比、帧率、模型质量、真实网站源码或用户参考视频的未观测信息。所有截屏来自实际工程。
- 不使用赛博风、荧光线、随机漂浮几何、模板音效、毫无价值的细小注释、覆盖主视觉的大卡片。
- 不可直接复制 Spyker/Heron/illoca 的受保护源码、视频、图片或独有设计资源。
- 保留 CC BY 4.0 车模的归属与修改记录；不得删除版权记录，仅合理调整展示位置。
- 不得要求用户反复确认显然已经给出的需求。

## 六、技术与测试约束

现有依赖：React 18.3.1、R3F 8.17.10、drei 9.117.3、Three.js 0.170.0、GSAP 3.12.6、Vite 6。**先适配当前实际依赖，不要为了“更新”而同时升级框架。** 如需 Playwright，安装到新工程 devDependencies；不允许复用 `tools/lineart/generate.mjs` 中写死的另一个比赛目录绝对路径。

单阶段验收必须同时包含：代码/构建证据，实际浏览器操作/截图（涉及视觉时），异常与反向操作。桌面1600×900为主验收，1440×900、390×844为辅助；Safari 与真机不可测时必须 UNVERIFIED。帧率需报告采样机器与方法，不能把 headless 61fps 描述成所有设备的60fps。

## 七、异常恢复/优先级

- 无原始高精模型：第04阶段标记 BLOCKED，保留当前 opt 版继续做可执行的开场/布局/镜头；第09阶段内饰细节如果无法验证，应保持明确的 UNVERIFIED，不能以外视图冒充内饰。
- REA 无法运行/浏览器不支持：仅用可访问的参考站、上传录屏、手动 DevTools/Playwright 取证，不阻断施工。
- 模型/网络加载失败：保留可靠错误提示与重试按钮，不自动无限重试。
- 性能不达标：先缩短冗余后处理和优化高成本材料，不通过牺牲主视觉质量“假完成”。
- 截止时间紧：优先保障开场、车模表现、摄影镜头、双栏、真实座舱、最终三张展板；车门开合等旧可选项不要做。
